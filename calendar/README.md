# Календарь материалов (POSTER)

Параллельный сервис к панели **POSTER**: пользователи загружают видео, обложку и тексты под сети; админ видит очередь и экспортирует папки + JSON для постера.

## Запуск (локально)

```bat
Z:\ai\bridge\venv\Scripts\python.exe -m pip install -r calendar\requirements.txt
start_calendar.bat
```

Откроется http://127.0.0.1:8767/

Демо-логины (сменить перед VPS):

| Логин   | Пароль   | Роль  |
|---------|----------|-------|
| admin   | admin    | админ |
| author  | author   | автор |
| maria   | maria    | второй автор (демо на общем календаре) |

При первом запуске создаются **демо-карточки** (префикс `demo-` в id): черновики, на проверке, одобрено — даты относительно «сегодня».

## Что уже есть (MVP)

- ЛК автора: плитки своих загрузок, **недельная сетка Пн–Пт** (слоты 09–11 … 19–21), перетаскивание карточек, «+» в пустом слоте.
- Форма: видео, обложка, описания для Instagram / TikTok / YouTube / VK (лимиты из `sites.json`).
- Замена видео/обложки/текстов — старый файл удаляется.
- Админка: все материалы, **правка текстов** (общий + по сетям, коллабораторы/отметки IG), смена статуса, **экспорт в POSTER** → `posts/NNN.*` + sidecar `.tags.txt`, `.collaborators.txt`, `.reel_tags.txt`.

## Связь с POSTER (следующий этап)

Панель/postер прочитает `poster_schedule.json` и возьмёт `schedule_start` и имена папок/файлов. Пока экспорт ручной по кнопке в админке.

## Данные

- SQLite: `calendar/data/calendar.db`
- Файлы: `calendar/data/uploads/<submission_id>/`
- Не коммитить `calendar/data/` (см. `.gitignore`).
